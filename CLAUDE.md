# Ferri: build rules for coding agents

Ferri is one AI teammate for community event organizers, built on Switch (https://github.com/sandbox-quantum/switch). It answers the community on every platform, turns unknown questions into cards for the crew, and turns crew decisions into updates outside.

## Layout
- `packages/switch`: our client for the Switch agent protocol (SSE down, HTTP up). See `../switch/docs/official/internals/agent-protocol.md`.
- `apps/ferri`: the Ferri agent service.
- `packages/db`: Drizzle schema, SQL migrations (`migrations/`), `createDb`, `runMigrations`, `getState`/`setState`.
- `packages/knowledge`: seeding from markdown, loading and searching the live knowledge, prompt rendering, triage, answering with sources, the Switch library mirror. Shared with the future `apps/desk`.
- `apps/ferri/src/flow.ts`: the message flow. `decideAction` (packages/knowledge/src/policy.ts) decides per message from the space's mode, the pause, the mute list and the sender; the flow then answers, logs, opens cards or stays quiet.
- `apps/ferri/src/loop.ts`: the learning loop: open or join question cards, poll card outcomes, resolve and fan out answers, the nudge/escalate/expire ladder.
- `skills/`: markdown skill files Ferri loads (`ferri.md` is the base persona, `librarian.md` the answer rules).
- `seed/`: demo community and event (made up: Lantern Labs, Lantern Build Night). Replace when the real community is chosen.
- `infra/docker-compose.yml`: Ferri's Postgres 16 with pgvector on port 5433 (Switch's Postgres holds 5432).
- `scripts/`: `setup-switch.ts`, `kb.ts` (`pnpm kb ...`), `eval-answers.ts`, `dev-mattermost.ts` (test people meera, arjun, priya; shared password `MM_TEST_PASSWORD` in `.env`).
- `apps/desk`: Desk, the organizers' dashboard (Next.js 16, App Router, Tailwind 4) on port 3100. Sign-in with a Switch account through the Gateway; server components and server actions read and write Postgres through `@ferri/db`; cards are answered through the Gateway as the signed-in person.
- `apps/desk/app/m`: Ferri Pocket, the crew's PWA (Needs you, a card, Who is stuck, Me). `public/m/sw.js` is its service worker (scope `/m`). `lib/pocket.ts` reads its data; `lib/cards.ts` answers cards through the Gateway for Desk and Pocket.
- `apps/ferri/src/launch.ts`: announcements (one approval card per version; post to every Auto/Approve space; later versions edit the posts in place through the fork's edit route), scheduled posts, crew reminders, team rooms from a Switch template. `packages/knowledge/src/launch.ts` holds its model calls (drafter, crew-chatter decision check), targets, time helpers and the Desk/Pocket writers.
- `apps/ferri/src/plan.ts`: the Plan stage (spec 08): reads the crew room's chatter into `plan_items` (decisions, owners, tasks with deadlines, open questions), the agenda draft with one `plan` card per decision, deadline reminders, knowledge for confirmed member-facing decisions, and the plan as a Switch library document attached to the crew room. `packages/knowledge/src/plan.ts` holds its model calls (`readPlanChat`, `draftAgenda`), rendering and `applyPlanOwners` (used by `loadCrew`, so plan owners route cards).
- `packages/shield`: Shield's checks (pure, no network: secrets, scam and lookalike links, floods, community rules), the optional Safe Browsing lookup, the `shield_events` log and `shield_rules`. `apps/ferri/src/shield.ts` serves `POST /guardrails/check` on 127.0.0.1:3200 for Switch Trust and alerts the crew.
- `packages/push`: Web Push (VAPID): subscriptions per Switch user, `pushToUsers`, the notice texts. Ferri's loop pushes on card open, nudge, escalate, expire and when a card is settled (same tag, so the notice is replaced).
- Ferri Builder (spec 11): `builder/` is the Builder's workspace template (CLAUDE.md, `.claude/settings.json` permission rules), copied by `pnpm builder:setup` to `~/.ferri/builder` (its own folder, outside the repo; its Claude home is `~/.ferri/builder-claude-home`, its controller env `~/.ferri/builder.env`). `scripts/builder-setup.ts` enrolls the machine, has Ferri create the Builder (`create_agent`), sets addressing and budget; `scripts/builder-controller.ts` runs the Switch agent controller. `apps/ferri/src/builder.ts` hands jobs over and reads reports; `packages/knowledge/src/builder.ts` holds the job table helpers, the hand-off text and the report parser; Desk's `app/(desk)/builder` and `lib/builder.ts`, Pocket's `builder-cards.tsx`. Spec 12: `builder/kits/event-site` is the event site kit (Next.js 16, `@supabase/ssr`, plain CSS, `supabase/migrations`, `scripts/supabase-up.mjs` and `scripts/vercel-env.mjs` that never print secrets) and `builder/.claude/skills/ship-event-site` the Builder's skill for it; setup writes `~/.ferri/builder/.ferri/site.json` (Supabase org and region, Vercel scope, hook URL and secret, admin emails). The site reports to Desk's `POST /api/site` (bearer `FERRI_SITE_HOOK_SECRET`, open in `proxy.ts`), stored in `site_events`; Ferri's builder tick tells the crew. Spec 13: `builder/kits/posters` is the poster kit (Satori and resvg, no browser): `scripts/art.mjs` makes background art with the OpenAI Images API (`gpt-image-2.6-flare`, one call per job by default, at most `maxCallsPerJob`, logged in `art/calls.json`, the key never printed), `scripts/render.mjs` draws the exact text, logo and QR code on it in six formats (A4 poster PNG/JPEG/SVG plus a 1240 px preview, square, 4:5, story, link card, X) and fails unless every character is in the fonts and every QR code reads back as the URL; `example/` is a made-up event for `--example`. `builder/.claude/skills/make-posters` is the Builder's skill. Setup writes `~/.ferri/builder/.ferri/studio.json` (model, quality, call limit), copies `seed/assets/` (the community's logo) to the Builder's `assets/community/`, installs the kit once, and puts `OPENAI_API_KEY` in the Builder's env file. When a poster job reports done, Ferri reads the Builder's images from the room (`read_context`), keeps them on `builder_jobs.media`, and opens an announcement card with the square JPEG (`announcements.media`); one OK posts the image with the caption through `SwitchAgent.sendMedia`. Desk shows a job's rendered PNGs as thumbnails.

## Conventions
- TypeScript, Node 22, ESM, pnpm workspace. Run with `tsx`. Check with `pnpm typecheck` and `pnpm test`.
- Relative imports name the `.ts` file (`import { x } from "./store.ts"`; `allowImportingTsExtensions`). tsx, Node and Next/Turbopack all resolve that; Turbopack does not map `./x.js` to `x.ts`.
- Models: `claude-sonnet-5-5` for answers, planning and drafting in production; `claude-haiku-5-5` for per-message triage. Use the official `@anthropic-ai/sdk`.
- Testing always uses `claude-haiku-5-5` at low effort (set `FERRI_MODEL_MAIN=claude-haiku-5-5` in `.env`). Do not spend Sonnet credits on tests.
- Switch sequence numbers can exceed `Number.MAX_SAFE_INTEGER`. Keep cursors as strings.
- Facts about the Switch API come from reading `../switch` (our fork, checked out next to this repo). Do not guess endpoints.
- Every feature works end to end on the real local stack before the next one starts.
- Commits: the repo owner is the only author. No AI attribution anywhere.
- Ferri never posts notices about reading messages or storing data. This is the owner's decision.
- Schema changes: edit `packages/db/src/schema.ts`, run `pnpm db:generate`, commit the new file in `packages/db/migrations/`. Ferri runs migrations on start. `0000_extensions.sql` is hand-written (pgvector).
- Ferri answers only from the knowledge tables and must cite a real entry; an answer without a valid citation is downgraded to the holding reply in code (`finalizeAnswer`). Keep that check.
- Run `pnpm eval:answers` after any change to a prompt, a skill file or the answer flow.
- On Windows, stopping `pnpm start` from a background shell can leave the `node` child running (two Ferris on one connection). Check with `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` and stop the old one.

## Running locally
1. In `../switch` (branch `ferri/agent-message-edit`): `docker compose -f deploy/local/standalone-docker-compose.yml --profile collab --profile gateway --project-directory . up -d`, then build Ferri's core image (`docker build -f deploy/local/ferri/Dockerfile --build-arg BASE=ghcr.io/sandbox-quantum/dev/switch-core:<SWITCH_VERSION> -t ferri/switch-core:local .`) and run it with `-f deploy/local/ferri/compose.override.yml ... up -d switch`. Without it, announcement edits fall back to a new "Update:" post.
2. Here: `pnpm install`, `pnpm db:up`, `pnpm setup:switch`, `pnpm dev:mattermost`, `pnpm kb seed`, then put `ANTHROPIC_API_KEY` in `.env`, then `pnpm dev`. `pnpm kb seed` also discovers Ferri's rooms and attaches the spaces `event.yaml` names.
4. Desk: `pnpm desk` (dev) or `pnpm desk:build` then `pnpm --filter @ferri/desk start`, at http://localhost:3100. Sign in with the Switch admin (`admin@switch.local`, `GATEWAY_ADMIN_PASSWORD` in `../switch/.env`).
5. Pocket: http://localhost:3100/m on the laptop. On a phone: the named tunnel `ferri` (`cloudflared tunnel run ferri`, config in `~/.cloudflared/config.yml`, example in `infra/cloudflared.example.yml`) serves Desk at https://ferri.rudratechie.xyz (Pocket at `/m`). Run Desk as the production build there (`pnpm desk:build`, then `pnpm --filter @ferri/desk start`); the allowed host is baked in at build time from `POCKET_ALLOWED_ORIGINS`. Ladder test timings: start Ferri with `FERRI_NUDGE_SECONDS=60 FERRI_CARD_TTL_SECONDS=300`.
6. Builder: build the controller once in `../switch/console` (`npx pnpm@10.28.2 install --filter "@switch-console/agent-controller..."`, then `npx pnpm@10.28.2 -r --filter "@switch-console/agent-controller..." run build`), then `pnpm builder:setup` and keep `pnpm builder:controller` running in its own terminal. Stopping the controller stops the Builder. Testing runs the Builder on `claude-haiku-5-5` at `effort: low` (`FERRI_BUILDER_MODEL`, `FERRI_BUILDER_EFFORT`; re-run setup after changing them).
7. WhatsApp (spec 10): in `../switch`, put `WAHA_API_KEY` in `.env` and add `waha` to `OUTBOUND_ALLOWED_PRIVATE_HOSTS`, start the sidecar (`docker compose -f deploy/local/standalone-docker-compose.yml -f deploy/local/ferri/compose.override.yml --profile whatsapp --project-directory . up -d waha`), then `pnpm whatsapp:pair` here: it adds the `whatsapp_web` connection (chats from `FERRI_WHATSAPP_CHATS`, default `me,Lantern Build Night`) and writes the QR code to `%TEMP%erri-whatsapp-qr.png` (`--code <number>` for a pairing code). A chat becomes a room with its first message; Desk's Add Ferri, then attach.
3. Open Mattermost at http://localhost:8065 (user `user`, password `MATTERMOST_USER_PASSWORD` in `../switch/.env`), go to `ferri-lab`, and say `@ferri when does hacking start?`.

## Switch behaviour to remember
- `payload.addressed` is true for an `@ferri` mention, in a direct chat, and for a "follow-up": the sender's next top-level message within 5 minutes of Ferri answering them, or a reply in Ferri's thread (feature flag `follow_the_conversation`, `delivery/conversation.py`). Ferri checks for a real mention itself and runs triage on follow-ups.
- When Ferri is offline, Switch itself replies to a mention with "I'm currently offline". Ferri catches up from its cursor when it comes back and answers messages younger than 10 minutes.
- Ferri's rooms: the `list_rooms` op lists every room Ferri is a member of. Mattermost channels are bridged automatically and Ferri sits in Town Square and Off-Topic; they are spaces that stay Off until attached.
- Question cards: `POST /agent-sessions/{session}/approvals` (any session id; Ferri uses `ferri-cards`). Switch escapes @mentions inside a card (zero-width space), so Ferri pings owners in a message of its own. A typed written answer needs quotes: `A1 "text"`. Ferri polls `GET /agent-sessions/approvals/outcomes` (the `approval_outcome` stream frame needs protocol revision 4+) and acknowledges with `.../delivered`. Switch renders a card it expired as "answered", so Ferri closes its cards itself before Switch's expiry. The card post is not in `read_context`.

- Outside platforms: a bridge is added with `POST /gateway/collaborations` (`bridge_type` telegram, slack, discord). A chat becomes a room when the bot lands in it (Discord: on its first message); Ferri joins with `!invite-agent @ferri` or `POST /gateway/rooms/{id}/agents`. `get_room_detail` gives `bridge_id` and the connection's display name, not the platform: `roomPlatform` asks the Gateway for the bridge type, then falls back to a platform named in the display name.
- Mentions: each bridge rewrites `@<platform username>` into a native mention (Slack `<@U…>`, Discord `<@id>`, Telegram user link). The username must be the raw one from `sender_name`; the sender id holds a folded copy (lowercase, `[^a-z0-9_-]` to `-`), so `parseSender` prefers `sender_name` and crew handles and the mute list compare folded forms (`sameHandle`).
- Slack and Discord turn a typed `@ferri` into a mention of the bot user when its name starts with "ferri", and the message then misses Ferri. The platform bot and app are named "Switch".
- A crew member is linked to a Switch account by `handles.switch = <email>` (Pocket's Me tab or `pnpm crew:account`). Pushes reach crew through that link; a Desk or Pocket answer is credited to that crew member's name.
- A service worker's scope must contain the page: `/m` is outside scope `/m/`, so Pocket's worker uses scope `/m` (header `Service-Worker-Allowed: /m`).
- A new Mattermost channel becomes a Switch room only when the bridge bot is in it, and adding Mattermost's `ferri` bot user to a channel puts Ferri in that room too. `GET /gateway/rooms` names rooms by the raw chat name ("build-night"); Ferri's spaces use the agent's room detail name ("Pulse Slack: build-night"), so Desk builds that form from `bridge_display_name`.
- `POST /gateway/rooms` refuses an internal room without an agent ("Internal rooms require at least one agent").
- Question cards draw buttons on Telegram (inline keyboard), Slack (Block Kit) and Discord (buttons); typed `A1 "text"` works on all of them, even with Slack's curly quotes.
- Upstream Switch has no agent message edit. Our fork adds `POST /agents/{agent_id}/messages/{event_id}/edit` (`{room_id, content}` returns `{ok, edited}`): own messages only (403 otherwise), Switch Trust on the new text, then the bridge's message map and `adapter.update_message` (Telegram re-attributes the agent name in the body). Switch's room history keeps the original text. `SwitchAgent.editMessage` calls it.
- Templates (`create_room_from_yaml`, version 2) can make real platform channels: a room with `bridge: <connection display name>`, `channel_type`, `users` (platform usernames) and `agents` (names of existing agents, so Ferri works). The kickoff is posted as "Kickoff from ferri, Admin's agent".
- Switch Trust (`core/switch_core/trust`): `POST {endpoint}/guardrails/check` with `{messages:[{role, content}]}`, headers `x-flintai-api-key`, `x-guardrails-policy-id`, `x-agent-session-id` (the room); no sender. Answer `{outcome: GUARDRAIL_RESULT_OUTCOME_OK|BLOCKED|REDACTED|ALERTED, findings:[{category, detector_name, severity, detected_string}]}` within 2 s or it fails open. A blocked member message is not relayed into the room (the platform post stays, Switch posts a notice to the sender); REDACTED swaps each `detected_string` for `[redacted]`. Settings: `PUT /gateway/trust-settings {endpoint, policy_id, api_key}`. From the Switch container, `host.docker.internal` reaches services bound to the host's 127.0.0.1.
- While Trust is on and Shield is down, Switch adds "Switch Trust could not check this message" to every message. Keep Ferri running, or `pnpm shield:connect --off`.
- Switch room documents (`create_room_document` op) need a caller bound to exactly one room; Ferri's connection covers every room ("This connection covers several rooms"). Ferri's per-room documents are library documents attached to the room (`publishLibraryDocument`).
- Model times: give "Now" with seconds (`localNow`), or "in 2 minutes" is rounded to the minute.
- Do not write TypeScript through a Python or bash heredoc with a backslash-n escape in it: Python turns it into a real newline. Use the Edit tool.
- Agent management (flag `agent_management`): an agent with `can_manage_agents` (owner sets `PUT /gateway/agents/{id}/can-manage-agents`) may `list_machines`, `create_agent`, `list_managed_agents`. `create_agent` refuses a machine whose last status has not reported the provider yet (`provider_not_installed` right after the controller starts): wait for the first status. Definition: `{provider, model, advanced_config: {effort, permissionMode, ...}, instructions, auto_mode, auto_approve, directory, isolation}`; change it with `PATCH /gateway/management/agents/{id}`.
- The headless controller (`console/packages/agent-controller`, no published release yet: build it from the checkout) runs on Windows with `run`; `install-service` refuses on Windows. `--server http://localhost:8000` is allowed (plain http only for loopback). `--env-file` passes `ANTHROPIC_API_KEY` and `CLAUDE_CONFIG_DIR` to sessions; without its own `CLAUDE_CONFIG_DIR` a session loads the organizer's personal `~/.claude` (plugins, hooks, MCP servers).
- A managed Claude Code session loads its folder's CLAUDE.md and `.claude/settings.json`. Its permission prompts (`ask` rules) and `AskUserQuestion` become Switch cards in the room it works in (`GET /gateway/agent-sessions/approvals` lists them for the owner; answer with `.../answer` `{answer: option_id}` or `{answers: [...]}`). Who may answer is the agent's addressing policy. Its activity (steps, tool calls, time) is a Switch activity card posted as a thread reply.
- Agents' messages arrive with `sender` `@switch-agent-<id>:<server>` and `sender_name` the agent's name; `sender_kind` is not always set. Ferri never treats them as member questions or crew chatter.
- `send_targeted_message` (and every op that acts on "the connected room") needs one room: Ferri calls it through `SwitchAgent.roomOp`, which sends `X-Switch-Connection-Id` plus its own `X-Switch-Session-Id` (`ferri-room-<room>`) and `connect_to_room` once per room. Ferri's stream still covers every room.
- A typed card answer (`A38 2`) also reaches a managed agent as a follow-up; the Builder's CLAUDE.md tells it to ignore those.
- Builder sessions get only allowlisted variables (`agent-env.ts`): provider keys, `CLAUDE_CONFIG_DIR`, and on Windows `APPDATA`, `LOCALAPPDATA`, `USERPROFILE`, ... So the Vercel CLI login (`%APPDATA%\com.vercel.cli`) and the Supabase CLI login (Windows credential store) work in sessions; `VERCEL_TOKEN` and other custom variables do not reach them (use a file in the Builder's folder).
- Claude Code permission precedence is deny, then ask, then allow, whatever the specificity: an `ask` rule must name only the public commands (`npx vercel deploy`, `--prod`, `promote`, ...), or it also gates `npx vercel env`.
- Supabase's built-in email sender only mails the project's team; the site kit creates confirmed accounts on the server instead.
- Do not open isolated browser contexts through the DevTools MCP in Opera: it restarts the browser.
- Agent media: `POST /agents/{id}/rooms/{room}/media` (multipart `files`, optional `caption`, `thread_id`) posts native image events that every bridge uploads as a real file; `GET /agents/{id}/rooms/{room}/media?mxc=...` downloads one. Media ids are `switch-media://<id>` (the field is still called `mxc`). A file sent with a message rides on that message's `attachments`.
- Switch delivers to an agent only what is addressed to it: Ferri never sees the Builder's own posts (files, captions) on its stream. Read them with `read_context` (`room_id`, `since`); entries carry `attachments`.
- Bridge uploads time out on big files: Mattermost after 10 s (a 5 MB PNG: "sent an attachment that couldn't be relayed"), Telegram on a 1 MB PNG even when the photo landed (then a duplicate "couldn't be relayed" note). Post JPEGs of a few hundred KB.
- Switch resumes one Claude session per managed agent across jobs and controller restarts, so a skill edited later is not re-read unless the agent calls it again; the hand-off tells the Builder to call its skill every job. `!reset @builder` typed by a person in the room starts a fresh session; an agent's `!reset` is just a message, and the Gateway's `POST /gateway/chats/{room}/controls` needs a signed-in member of the room. The controller reads `--env-file` only at start: restart it after `pnpm builder:setup` changes the env file.
- WhatsApp (`whatsapp_web`, our fork, spec 10): a WAHA sidecar (GOWS engine) linked to the user's own number. Only the groups in the connection's `chats` (names or ids, `*` for all), named direct chats and `me` (the "Message yourself" chat) become rooms. Agents post as "*Ferri:* ..."; posts are paced (typing, 3 s per chat, 30 an hour, refused past the cap). A note to self arrives under the account's LID (`…@lid`). The connection must be created with `channel_creation_enabled: false`, and Switch needs `OUTBOUND_ALLOWED_PRIVATE_HOSTS` to include `waha`.
- Budgets: `POST /gateway/tenants/{tid}/budgets {agent_id, metric, model: "", amount_limit, period_hours}` (`GET /gateway/tenants/current` for the id). A spent budget: Switch answers a mention of the agent with "Agent X has reached its budget of ..." in the room and starts no session. Periods reset at fixed times (00:00 UTC for 24 h).
